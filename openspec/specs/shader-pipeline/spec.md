# shader-pipeline

## Purpose

Describes how a WGSL shader is authored, preprocessed, and delivered to the GPU: the module system
and its `//! import` resolution, the `{{PLACEHOLDER}}` substitution that injects Nim-owned constants,
and the two mutually exclusive delivery routes — HTTP fetch for compute shaders, `staticRead`
embedding for render shaders — with their opposite registration requirements. It is one capability
because authoring, bundling, and delivery share a single artifact: the bundled file at
`web/shaders/<name>.wgsl`. Nothing else reads that file, and every rule about it is a rule about how
one shader reaches the device.

The byte layout of a GPU struct, and the compile-time offset assertions that pin it, belong to
`gpu-buffer-layout`; this spec owns only how the module carrying that struct is assembled and
delivered. Which shaders a mode dispatches, and in what order, belongs to `gpu-frame-registry`; this
spec owns the manifest's own internal consistency and its relation to what the server serves. The
order of build stages across the whole project belongs to `build-pipeline`; this spec owns what the
`shaders` stage does and what it refuses to produce.

## Requirements

### Requirement: Shaders authored in source and modules, delivered as generated bundles

Every WGSL shader SHALL be authored in exactly one of two places: a source shader under
`web/shaders/src/` (one file per shader that reaches the GPU) or a shared module under
`web/shaders/modules/` (reusable declarations imported by source shaders and by other modules).

The bundled files at the top level of `web/shaders/` SHALL be build output and MUST NOT be edited.
`tools/wgsl_bundle.nim:188-194` stamps each one with an `AUTO-GENERATED BY tools/wgsl_bundle.nim -
DO NOT EDIT DIRECTLY` banner naming its source path and its inlined modules, and `.gitignore:9-10`
excludes `web/shaders/*.wgsl` from version control, so an edit to a bundled file is destroyed by the
next build rather than committed.

The `shaders` build stage (`justfile:22-23`) SHALL be the only producer of those files. It compiles
and runs `tools/wgsl_bundle.nim`, which walks every `web/shaders/src/*.wgsl` and writes one bundled
file of the same name into `web/shaders/` (`tools/wgsl_bundle.nim:325-336`). A source shader that is
never bundled has no artifact for either delivery route to pick up.

Enforced by: `tools/wgsl_bundle.nim` (the banner and the walk), `.gitignore:9-17`, `justfile:22-23`.
That a hand edit to a generated file is not made in the first place is **review-enforced**; the build
only guarantees it does not survive.

#### Scenario: A bundled file is edited directly

- **WHEN** a top-level `web/shaders/*.wgsl` file is edited by hand and the build runs
- **THEN** the bundler rewrites that file from its `src/` source and the edit is lost, and the edit
  was never committable because `.gitignore` excludes the path

#### Scenario: A new source shader is added

- **WHEN** a new file is added under `web/shaders/src/`
- **THEN** the next run of the `shaders` stage writes a correspondingly named bundled file into
  `web/shaders/` without any registration step in the bundler itself

### Requirement: Import resolution is recursive, deduplicated, ordered, and fails the build on a missing module or a cycle

A shader or module SHALL declare a dependency with a `//! import <name>` directive at the start of a
line, naming a module resolved as `web/shaders/modules/<name>.wgsl`
(`tools/wgsl_bundle.nim:46-56`, `:75`). Directives MAY appear in modules as well as in source
shaders, and resolution MUST be transitive: the bundler drains a worklist of pending imports, loading
each module's own imports as it goes (`tools/wgsl_bundle.nim:174-183`). Modules under
`web/shaders/modules/` exercise this — `cell_index.wgsl` imports `grid_params`, and
`tonemap_grade.wgsl` imports `tonemap_params`.

Each module SHALL be inlined at most once per bundle. `parseImports` deduplicates within a file
(`tools/wgsl_bundle.nim:49-56`) and the module cache deduplicates across the dependency graph
(`tools/wgsl_bundle.nim:70-72`). Inlined modules SHALL be emitted in dependency order — every module
before its dependents — via a Kahn topological sort (`tools/wgsl_bundle.nim:89-122`), with the main
shader body last (`:205-209`). Every `//! import` line MUST be stripped from the emitted output
(`tools/wgsl_bundle.nim:58-64`), because WGSL has no import syntax.

The bundler MUST fail the build, exiting non-zero, in two cases. An import naming a file that does
not exist under `web/shaders/modules/` quits with `Error: Module not found`
(`tools/wgsl_bundle.nim:76-77`). An import cycle quits with `Error: Circular dependency detected`,
detected as a topological sort that fails to emit every loaded module
(`tools/wgsl_bundle.nim:124-129`). Both failures happen at build time, in the `shaders` stage, before
any Nim compile consumes the output.

Enforced by: `tools/wgsl_bundle.nim:76-77` and `:124-129` (both `quit`, which exits with failure and
so fails `justfile:22-23` and the whole `just happen` chain).

#### Scenario: An import names a module that does not exist

- **WHEN** a source shader declares `//! import no_such_module` and the build runs
- **THEN** the bundler exits non-zero with `Error: Module not found: web/shaders/modules/no_such_module.wgsl`
  and no bundled output is written for that shader

#### Scenario: Two modules import each other

- **WHEN** module A imports module B and module B imports module A, and a shader imports either
- **THEN** the bundler exits non-zero with `Error: Circular dependency detected involving:` and the
  names of the modules it could not order

#### Scenario: A module is reached by two paths

- **WHEN** a shader imports both `cell_index` and `grid_params`, and `cell_index` itself imports
  `grid_params`
- **THEN** `grid_params` appears exactly once in the bundled output, ahead of `cell_index`

### Requirement: Placeholder substitution runs after inlining and fails the build on an unresolved placeholder

The bundler SHALL substitute `{{KEY}}` occurrences from the table returned by
`shader_config.getPlaceholderMap()` (`tools/wgsl_bundle.nim:136`, `src/shader_config.nim:185-266`),
and MUST do so **after** all modules are inlined — `bundle` builds the full concatenated output and
substitutes into it as its last step (`tools/wgsl_bundle.nim:212`). Placeholders therefore work
inside `modules/` exactly as they do in source shaders; `fixed_point.wgsl`, `colormap.wgsl`, and
`sph_kernels.wgsl` depend on this.

A source shader MAY write the shorthand `{{WORKGROUP_SIZE}}`, which resolves against the shader's own
filename: the bundler uppercases the filename and replaces hyphens with underscores to form the key
`WORKGROUP_SIZE_<NAME>` (`tools/wgsl_bundle.nim:143-145`). A shader needing two dimensions MUST name
the explicit keys instead, as the two-dimensional field passes do with `{{WORKGROUP_SIZE_FIELD_X}}`
and `{{WORKGROUP_SIZE_FIELD_Y}}` (`src/shader_config.nim:208-209`).

Any `{{...}}` pair surviving substitution MUST fail the build: the bundler quits with
`Error: Unreplaced placeholder in <shader>` (`tools/wgsl_bundle.nim:152-157`). A misspelled or
unregistered placeholder therefore cannot reach the GPU as literal text.

Every substituted value SHALL originate in Nim. Workgroup sizes and tuning constants come from
`activeConfig` (`src/shader_config.nim:84-126`); field dimensions and seed geometry from
`field_core`, the blur kernel from `bloom_core`, and the colormap ramps from `colormap_core`
(`src/shader_config.nim:174-183`, `:210-265`). No WGSL file restates a number that
`getPlaceholderMap` serves.

Enforced by: `tools/wgsl_bundle.nim:152-157` (build-time `quit`) and `tests/test_shader_config.nim`,
which checks the accessors and the emitted literals natively — that workgroup sizes are positive
multiples of 32, that the emitted fixed-point reciprocal inverts the emitted scale, that the emitted
bloom weight list has exactly `BLOOM_WEIGHT_COUNT` entries, and that the 2D field tile divides
`FIELD_W x FIELD_H` exactly.

#### Scenario: A shader references an unregistered placeholder

- **WHEN** a source shader or module contains `{{TUNABLE_NOT_A_REAL_KEY}}` and the build runs
- **THEN** the bundler exits non-zero naming the shader and the unreplaced placeholder, and no
  bundled output is written for that shader

#### Scenario: A tuning constant is changed in Nim

- **WHEN** a value in `src/shader_config.nim` changes and the build runs
- **THEN** every bundled shader whose placeholders draw on it is regenerated with the new literal,
  with no WGSL file edited

#### Scenario: A placeholder appears inside an imported module

- **WHEN** a module under `web/shaders/modules/` contains `{{TUNABLE_FIXED_POINT_SCALE}}` and a
  shader imports that module
- **THEN** the bundled output carries the substituted literal, because substitution runs on the
  concatenated result rather than on each file before inlining

### Requirement: GPU struct modules are generated from the Nim layout tables before imports resolve

WGSL modules that declare a uniform struct owned by `src/gpu_types.nim` SHALL be generated, never
hand-written. The bundler emits `sim_params`, `render_params`, `fade_params`, `field_params`,
`bloom_params`, and `tonemap_params` into `web/shaders/modules/` from the corresponding Nim layout
tables (`tools/wgsl_bundle.nim:280-299`), and MUST do so before any import is resolved
(`tools/wgsl_bundle.nim:319-320`), so a source shader can `//! import sim_params` like any other
module. These generated modules SHALL be excluded from version control (`.gitignore:12-17`); the
bundler recreates them on every build.

Each generated module MUST be rewritten only when its content changes
(`tools/wgsl_bundle.nim:264-271`), so its modification time tracks an actual layout change and the
mtime-based rebuild check stays accurate.

The field list and byte offsets these modules declare are owned by `gpu-buffer-layout`. This
requirement covers only that they are generated, generated early enough to be importable, and not
committed.

Enforced by: `tools/wgsl_bundle.nim:264-299` and `:319-320` (build step), `.gitignore:12-17`.

#### Scenario: A generated struct module is deleted

- **WHEN** `web/shaders/modules/sim_params.wgsl` is absent and the build runs
- **THEN** the bundler regenerates it before resolving imports, and shaders importing `sim_params`
  bundle successfully

#### Scenario: A Nim layout changes

- **WHEN** a layout table in `src/gpu_types.nim` changes and the build runs
- **THEN** the corresponding generated module's content changes, its modification time advances, and
  every shader importing it is rebundled

### Requirement: Compute shaders are fetched over HTTP and registered in both the manifest and StaticFiles

A compute shader SHALL reach the GPU by HTTP fetch at pipeline-init time. `initPipelines` collects
the `ShaderSpec` entries `shader_manifest.shaderSpecsFor(kind)` returns for each prewarmed simulation
kind, deduplicates them by key, and fetches each spec's `path`
(`src/webgpu_compute.nim:571-591`, `:511-514`). Every compute shader a mode needs MUST therefore have
a `ShaderSpec` in `src/shader_manifest.nim:34-103`, and every spec path MUST be a key in the
`StaticFiles` table in `src/main.nim:37-61`, which is the exhaustive set of paths the server answers —
anything else gets a 404 (`src/main.nim:78-87`).

A missing `StaticFiles` entry SHALL surface as a fetch failure at runtime, not at build time.
`loadShader` raises `Failed to load shader <path>` on a non-ok response
(`src/webgpu_compute.nim:513-514`). **No build step, compile-time assertion, or test relates manifest
paths to `StaticFiles` keys.** `src/main.nim` imports `webui` and `asynchttpserver` and so is not
importable by the pure native suite, and `StaticFiles` is referenced nowhere outside `src/main.nim`.
The native suite checks only the shape of a spec path — that it starts with `./shaders/` and ends in
`.wgsl` (`tests/test_shader_manifest.nim:80-86`) — which does not establish that the path is served.
Keeping the two tables in agreement is **review-enforced**, documented at `src/README.md:156`.

The `StaticFiles` table SHALL be `staticRead` at Nim-compile time, so the converse error is caught
early: an entry naming a file the bundler did not produce fails the native compile.

The manifest SHALL be internally well-formed: spec keys unique within a kind, since the pipeline and
bind-group dictionaries are keyed by them; spec paths need not be unique, because two keys MAY share
one shader file and entry point when they differ only in bind-group orientation
(`tests/test_shader_manifest.nim:66-86`, `:130-143`).

Enforced by: `tests/test_shader_manifest.nim` (manifest internal consistency and path shape, native),
`src/main.nim:37-61` (`staticRead` at Nim-compile time, in the direction StaticFiles → bundled file
only), `src/webgpu_compute.nim:511-514` (runtime failure in the direction manifest → StaticFiles).

#### Scenario: A compute shader is added to the manifest but not to StaticFiles

- **WHEN** a new `ShaderSpec` is added to `src/shader_manifest.nim` with no matching `StaticFiles`
  entry
- **THEN** the build succeeds and both test suites pass, and the failure appears only when the
  application runs and pipeline init raises `Failed to load shader ./shaders/<name>.wgsl`

#### Scenario: A StaticFiles entry names a shader the bundler does not produce

- **WHEN** `src/main.nim` lists a path with no corresponding bundled `web/shaders/*.wgsl` file
- **THEN** the native compile fails at the `staticRead`, before any binary is produced

#### Scenario: Two dispatch keys share one shader file

- **WHEN** two `ShaderSpec` entries in one kind carry distinct keys and the same path and entry point
- **THEN** the manifest is well-formed, one shader module is fetched, and the executor gives each key
  its own bind group over the shared pipeline

### Requirement: Render shaders are embedded by staticRead and stay out of StaticFiles

A render shader SHALL reach the GPU embedded in `web/app.js`. `src/webgpu_render.nim:148-159`
`staticRead`s the bundled `render`, `glow`, `fade`, `composite`, `field-composite`, `blur`, and
`tonemap` shaders into string constants at Nim-compile time, so they travel inside the frontend and
are never fetched.

Those shaders MUST NOT appear in the `StaticFiles` table. Serving them would ship the same bytes a
second time, once inside `app.js` and once over HTTP; `src/main.nim:54-55` records the exclusion for
`field-composite`, the case a reader is most likely to mistake for a compute shader because its name
matches the reaction-diffusion field passes.

A render shader that is absent or unbundled SHALL fail the frontend compile, because `staticRead`
resolves at Nim-compile time — a materially stronger check than the compute route's runtime fetch.

Enforced by: `src/webgpu_render.nim:148-159` (`staticRead`, Nim-compile time). That a render shader
stays absent from `StaticFiles` is **review-enforced**: nothing fails if it is added there, the bytes
are merely duplicated.

#### Scenario: A render shader source is deleted

- **WHEN** `web/shaders/src/glow.wgsl` is removed and the build runs
- **THEN** the bundler produces no `web/shaders/glow.wgsl` and the `nim js` frontend compile fails at
  the `staticRead`, before any runtime

#### Scenario: A new render shader is added

- **WHEN** a shader is authored for the render path and `staticRead` into `src/webgpu_render.nim`
- **THEN** it is not added to `src/shader_manifest.nim` and not added to `StaticFiles`, and it is
  delivered inside `app.js`

### Requirement: Rebundling is driven by modification times over declared inputs

The bundler SHALL rebundle a shader only when an input is newer than its output, and MUST treat
three classes of file as inputs: the source shader itself, every module it names in a `//! import`
directive, and the Nim modules whose constants feed placeholder substitution —
`src/shader_config.nim`, `src/field_core.nim`, `src/bloom_core.nim`, and `src/colormap_core.nim`
(`tools/wgsl_bundle.nim:218-254`). A missing output always rebuilds (`:231-232`). Including the Nim
sources is what stops a tuning edit from shipping silently stale shaders: such an edit changes the
bundled bytes without touching any `.wgsl` file.

The check covers a source shader's **direct** imports only; a module reached solely through another
module is not consulted (`tools/wgsl_bundle.nim:242-246`). Every source shader that depends on a
nested module also names that module in its own `//! import` list, which keeps the check complete —
that property is **review-enforced**, with no test or assertion behind it. A source shader that drops
a redundant-looking direct import while still depending on the module transitively would be skipped
after an edit to that module until its output is deleted or another input changes.

Enforced by: `tools/wgsl_bundle.nim:230-254` (build step); the transitive-import property is
review-enforced.

#### Scenario: A tuning constant changes with no shader edit

- **WHEN** `src/shader_config.nim` is edited and the build runs
- **THEN** every bundled shader older than that edit is rebundled, so no shader carries a stale
  substituted literal

#### Scenario: Nothing has changed

- **WHEN** the build runs twice with no edit between
- **THEN** the second run bundles nothing and reports every shader unchanged

#### Scenario: A shared module is edited

- **WHEN** a module under `web/shaders/modules/` is edited
- **THEN** every source shader naming that module in its own `//! import` list is rebundled

### Requirement: WGSL validity is established on the device, not by the build

The bundle step SHALL be a text transformation only — import inlining and placeholder substitution —
and MUST NOT be treated as a check that the resulting WGSL compiles. No build stage invokes a WGSL
compiler or validator (`justfile`), so a bundled shader that is syntactically invalid, declares a
binding the pipeline does not provide, or names an entry point that does not exist passes the build
intact.

Compute shaders SHALL be checked on the device immediately after module creation:
`validateShaderCompilation` reads `getCompilationInfo()` and raises with the offending line numbers
when any message is an error (`src/webgpu_compute.nim:171-188`, called at `:527`), and pipeline
creation is wrapped in a validation error scope that raises on failure (`:534-552`). Both are runtime
failures during pipeline init.

Render shaders SHALL be compiled through `createShaderModule` without an explicit
`getCompilationInfo` check (`src/webgpu_render.nim:211`, `:330`, `:408`, `:495`, `:623`, `:735`,
`:814`), so their errors surface through the device's own error reporting rather than a raised
exception naming the shader.

Enforced by: `src/webgpu_compute.nim:171-188` and `:534-552` (runtime, compute path). For render
shaders and for build-time WGSL validity there is no enforcement point — **review-enforced**, with
the working application as the check.

#### Scenario: A bundled compute shader has a WGSL syntax error

- **WHEN** a source shader contains invalid WGSL and the full build runs
- **THEN** the build succeeds and both test suites pass, and the failure appears at pipeline init as
  a raised `Shader compilation failed for "<label>"` carrying the line numbers

#### Scenario: A manifest entry names an entry point the shader does not define

- **WHEN** a `ShaderSpec` names an `entryPoint` absent from its shader file
- **THEN** the build succeeds and pipeline creation raises `Pipeline creation failed` at runtime
