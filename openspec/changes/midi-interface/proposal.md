# midi-interface

## Why

Particle Garden aims at expression, and its world answers only to pointer, keys, and panel. A MIDI surface puts the one-world model under the hands: continuous strengths on physical controls, gestures that touch the world on pads, and a shipped mapping whose defaults teach the model itself, four coupling strengths side by side with zero an ordinary value. The mapping lives in a control matrix built for more than one source family, so audio features can later join as sources without reshaping what this change builds.

## What Changes

- **A Web MIDI transport, acquired behind a panel affordance.** The browser's permission prompt fires on first use of a "connect MIDI" control rather than at startup, adopting the platform behavior deliberately (docs/engineering-principles.md, article 11). Device hot-plug is handled from the start through the API's state-change events.
- **A pure MIDI core, natively tested, blind to transport.** It consumes raw event triples plus the matrix and produces row firings. Web MIDI is its first producer. A native CoreMIDI relay can arrive later as a second producer without touching the core, and nothing in this change depends on that relay existing.
- **A control matrix, one spine for every mapped control.** A row admits only legal combinations, constructively: `Modulate(source, param, depth, slew)`, `Write(source, param, takeover)`, `Fire(event, action)`, `Touch(event, gesture)`. Modulating an action is unrepresentable. MIDI supplies the first source family (CC as continuous source, note, program change, and onset-like events), and each family normalizes at its own boundary (CC divides by 127), so past that point the matrix cannot tell families apart. The audio feature family is planned as a sibling change that adds sources and touches no matrix code.
  - *Write rows.* A source value becomes travel in [0, 1] and passes through the served curve to a lattice value (`src/ui/api/slider_curve.nim`), entering the same clamped, synchronous write path the panel and the weathers use (`src/web_api.nim:585-639`, mirror invariant at `src/web_api.nim:8-16`, precedent at `src/app.nim:244-269`). A knob therefore means exactly what its slider means: same curve, same lattice, same live ceiling. The value persists where the writer left it and saves into presets, since presets snapshot the stored record (`src/web_api.nim:135-160`).
  - *Modulate rows.* The excursion folds into the effective state at the one effect-time clamp site, where the mirror already lands `effectiveSimulation(storedState)` into `CONFIG` (`src/web_api.nim:135-160`, `src/ui/api/param_descriptor.nim:303-320`). The stored value, `getParam`, presets, and the slider's base all stay the user's own, and releasing the control returns the world to that base. The frame loop refreshes the mirror while any excursion is live, a cadence whose cost the weathers already pay with one batched write per frame (`src/app.nim:244-269`). Zero depth is an ordinary value.
  - *Fire rows.* Program change selects among the six named regimes (`src/web_api.nim:670-688`). Momentary actions (randomize matrix, reseed field, reset particles) and toggles (trails, bloom, the two weathers) reach their existing gardenAPI paths (`src/web_api.nim:1164-1295`).
  - *Touch rows.* A pad fires a blast at a world point through `InputState`, the path the two-finger tap takes (`src/canvas_input.nim:189-198`). Note number indexes a cell of the visible view, and velocity scales blast strength. `withBlast` gains a strength argument, since it pins strength at 1.0 (`src/ui/state/input_state.nim:60-64`).
- **Arbitration when rows collide on one parameter.** Modulation excursions sum and clamp against envelope and ceiling. Write rows carry a user-visible rank, the active source takes over, and the editor exposes the rank exactly where two rows collide. Rank orders sources without regard to family, so the user decides precedence between any two sources the same way.
- **A shipped matrix, user-editable.** Generic CC defaults lead with the four coupling strengths (`couplingsOf`, `src/ui/state/sim_config.nim:43-57`). Learn mode in the panel overrides any row. The matrix schema, validation, and shipped defaults live in Nim. The panel stores user matrices in localStorage under keys Nim serves, the split presets already use (`src/web_api.nim:1301-1311`).
- **A matrix row names no direction.** It associates a control with a target, so an outbound sender for feedback hardware can later subscribe to what already flows without reshaping the matrix. Outbound itself stays out of scope.
- **Soft takeover ships as the default for Write rows on absolute controls**, with jump selectable per row: a knob writes only after crossing the live value. The weathers move parameters on their own (`src/app.nim:257-269`), so writing on first touch would yank a drifting value to wherever the knob rests.
- **The stats push generalizes its outside-writes record and carries excursions.** The `params` record is built from the two enumerated weather id tables (`src/web_api.nim:811-830`), and the panel applies whatever arrives (`web-ui/src/state.ts:101-127`). It becomes the set of ids written outside the panel since the previous push, so a slider moved by a Write row stays truthful under a user-editable id set. The push also carries each live excursion beside the ceilings it already carries (`src/web_api.nim:842-848`), so the panel can shade a modulated parameter the way it shades a ceiling (`web-ui/src/components/ParamSlider.tsx:55-68`).
- **Continuous rows coalesce, events queue.** A control sweep collapses to the latest value per row and flushes once per frame beside the weathers, the batching the climate already performs (`src/web_api.nim:728-736`). Blasts and actions are events and queue instead.

Out of scope: the audio source family (planned sibling change), the CoreMIDI relay transport, MIDI output and feedback behavior, per-species targets and species-matrix cells, polyphonic held-pad attractors, 14-bit CC precision.

## Capabilities

### New Capabilities

- `midi-input`: transport acquisition and the permission affordance, event ingestion with per-frame coalescing, and MIDI's normalization into matrix sources feeding the existing write, effective-state, action, and gesture paths.
- `control-matrix`: the row model with its four kinds, arbitration (summed modulation, ranked writes), validation, the shipped pedagogical defaults, learn-mode editing, and persistence split between Nim-owned schema and panel-owned storage.

### Modified Capabilities

- `gardenapi-boundary`: the stats sample's `params` record carries every id written outside the panel since the previous push, replacing the enumerated weather tables, the push carries live excursions beside its ceilings, and the boundary serves the matrix surface (rows read, row edit, rank edit, learn state) the panel renders.

## Impact

- **Nim (JS backend).** A Web MIDI binding joins `src/bindings/`. New pure modules under `src/ui/input/` carry the matrix model and row derivation, with native tests beside the existing input suites (`tests/test_input.nim`, `tests/test_camera_input.nim`). `src/web_api.nim` gains the MIDI write entry, the matrix surface, the generalized outside-writes push, and the modulate arm inside the effect-time clamp seam (`src/web_api.nim:135-160`). `src/app.nim` wires the per-frame flush and excursion refresh, honoring its import-order constraint (`src/app.nim:8-11`). `src/ui/state/input_state.nim` extends `withBlast` with strength.
- **Panel.** A connect affordance and a matrix editor with learn mode and rank exposure at collisions. Sliders shade live excursions through the pattern the derived ceilings already use (`web-ui/src/components/ParamSlider.tsx:55-68`). The stats channel keeps its shape on the TypeScript side, which already applies whatever ids arrive.
- **Help.** MIDI controls and the matrix editor document under `docs/help/` in the same change that adds them, and the four test-held coverage relations extend to the new group (CLAUDE.md, Help).
- **Dependencies.** None added. Web MIDI is an API of the launched browser window.
- **Measurement gate.** Before transport work proceeds, a spike confirms `navigator.requestMIDIAccess` resolves with device access inside the webui-launched window on this machine, since browser selection belongs to webui (https://github.com/webui-dev/webui). If the launched browser refuses, the affordance reports unavailability, and the core stays blind to the outcome either way.
